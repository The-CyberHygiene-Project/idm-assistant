# ISO 0.7.0 known issues

These are the known limits of the 0.7.0 document server and the controlled-document workflow. Each one that needs a
POA&M row has its id (T-08 to T-16); the rows are in `appliance/site-stick-kit/poam-seeds-0.7.0.md`. The user
guide is the chapter "From 0.7.0 on: controlled documents" in `appliance/site-stick-kit/SITE-STICK.md`.

0.7.0 is for **new installs only**. An existing site moves by reinstalling.

## Limits that stay in 0.7.0

### The database cannot do MD5 (T-08)

PostgreSQL in FIPS mode refuses `MD5()`, which NextCloud uses for some moves. The server refuses those moves
(DEGRADED mode) so that nothing is left half-moved.

- Refused: moving, renaming or deleting a folder with files in it; moving a file that has old versions to another
  team folder.
- Works: files, copies, empty folders, CUI to Archive and Archive to CUI for a file without old versions.
- `chp-site documents status` and the nightly check show "DEGRADED: database MD5 unavailable". The first refusal each
  day raises a level-7 alert.
- A publish of a CUI document is refused, with nothing changed, when the published file has old versions.
- The refusal stops by itself when the database can compute MD5. The upstream defect report is the owner's to file.

### fapolicyd filesystem marks are off (T-09)

fapolicyd 1.4.3-3 (Rocky 9.8) exits about a second after a restart with `allow_filesystem_mark = 1`
("recvmesg failed"). The marks therefore stay off (`FSMARK=0`). Files that services open in their own mount
namespace are not checked by fapolicyd.

The same exit can follow any fapolicyd restart, also with marks off. `chp-site documents enable` restarts fapolicyd,
checks it three times, restarts it once more if it is dead, and fails if it is still dead. Monitor check 80 alerts
until it runs again. The trial is repeated when Rocky ships a fixed version.

### The editor's crypto is not validated (T-10)

ONLYOFFICE Desktop Editors bundles Chromium with BoringSSL, which ignores the system's FIPS mode. Chromium runs with
`--no-sandbox`, and the app runs unconfined. The editor makes no network connection of its own: its network features are
blocked, and `chp-site doc` does the transport with the system OpenSSL.

The controls proven so far are the removed AI Tools plugin, the egress table and the hosts block. The settings-file keys
that hide AI entries and turn off plugins and portals are defaults whose effect is not proven.

### PHP 8.3 (T-11)

NextCloud 35 runs on PHP 8.3. Later releases need a newer PHP. The move (a newer PHP stream, or Rocky 10) is planned
before NextCloud 37.

### The OIDC code appears in NextCloud's audit log (T-12)

The sign-in callback's address, with the single-use OIDC `code` and `state`, is written to the audit log and reaches
the Wazuh index. The code is bound to the client secret and to PKCE and expires within minutes. NextCloud's log writer
is not ours to change. Both records are CUI-boundary records.

### The ledger can be forged on the server, and is watched (T-13)

A compromised NextCloud could replay a live approver token. Anyone with a shell on the server can write false
`chp-docs-ledger` journal lines with `logger -t`, and so raise a false level-12 alert. A false line never hides a real
event: check 82 and the daily review trust only the ledger and root's journal lines. Every approval and every ISSO
override alerts at once. The residual is accepted with detection.

After any Wazuh upgrade, prove again that the ledger lines still reach the level-15 base rule (100640) and its
children, not a stock rule.

### DNS tunnelling through the site resolver (T-14)

A workstation may send DNS to the site resolver, which forwards upstream. DNS to any other server, DNS over TLS and
DNS over QUIC are refused. Data hidden in DNS names to the resolver is not stopped.

### Two accounts live outside Kanidm (T-15)

`chp-publisher` (the ledger appender's account) and `chp-canary` (the nightly share test) are local NextCloud
accounts. Neither has a usable password. Record them in the SSP and name an owner.

### The banner check reads text only (T-16)

A CUI banner in a white or 1-point font passes the check. A missing banner, a banner in a text box, and hidden or
deleted text do not pass.

## Limits of use

- **Download and re-upload.** A person who can download CUI can upload it elsewhere. The owner accepted this as an
  insider risk. Every download and upload is logged. The site rule: CUI from the document server is never uploaded
  outside the CUI folders (SSP 3.1.3).
- **FCI marking is under review.** FCI documents carry the CUI banner as built.
- **Server memory.** The server needs at least 8 GiB.
- **Alert text carries CUI file names and paths** and goes to `ALERT_HOOK`. The site delivers it only inside the CUI
  boundary.
- **Hand-off of a draft** to the approver is a browser upload to an ordinary CUI (or Internal) folder and a download
  by the approver. The approval is bound to the file's sha256, so the transport needs no trust. The approver must not
  run `doc checkout`.
- **Workstations.** `KillUserProcesses=yes` and an hourly `disable-linger` apply to all accounts, so an
  administrator's `tmux` or `screen` session ends at logout. The whole workstation is confined to the site server and
  the site resolver, Firefox included. A failed egress table at boot leaves only loopback (Wazuh 100628, level 12,
  which arrives after recovery; the first live signal is the server's agent-disconnected check 71).
- **The reader PDF** is made with ONLYOFFICE's converter, which the vendor does not document as a supported interface.
  ONLYOFFICE must have been started once by the person who publishes.
- **The clock.** The sign-in is refreshed 60 seconds before it ends, which assumes chrony keeps the workstation
  clock right.
- **Pending requests.** A command that ends with exit 3 is run again with the same words; its request id is kept
  across `chp-site doc logout`.

## Alerts that surprise people

- The first `chp-site documents enable` raises rule 100623 (level 12) twice: the break-glass admin account is made and
  added to `admin`. Tell the ISSO first.
- Running `chp-site documents check` by hand outside 03:05-03:45 enables `chp-canary` and raises rule 100609
  (level 12), like an intrusion.
- Rule 100629 (level 12) pages once for each new CUI reader's first sign-in.
- A missed night (the server was off at 03:10) is not caught up: there is no tag check and no canary for up to about
  48 hours. Check 81 alerts when its result is older than 26 hours.
- Events that NextCloud writes while the Wazuh manager restarts may not be analysed. The audit file keeps every line.
- Check 82 reports "not checked this run" when the appender holds the ledger lock. It alerts after 4 runs in a row.
