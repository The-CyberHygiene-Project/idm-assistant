# ISO 0.7.0 Plan 1: NextCloud spike and the deferred minors

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** answer every "(builder)" and spike question in the 0.7.0 design with lab evidence (so Plan 2 can pin
interfaces), and fix the deferred minors from the 0.5.0-update1 and 0.6.0 reviews.

**Architecture:** two independent tracks on one branch. Track A is a throwaway spike on a dedicated lab VM pair
(results recorded in `lab/docs-spike/SPIKE-NEXTCLOUD.md`, nothing shipped). Track B is test-first fixes to existing
chp-site code, chp-base check 76, the tests and the lab scripts. **Plan 2** (NextCloud role, doc workflow,
templates, release) is written from Track A's findings after this plan.

**Tech Stack:** Rocky Linux 9 (FIPS, SELinux enforcing, fapolicyd, OpenSCAP CUI), NextCloud (current stable),
Kanidm 1.11, Wazuh 4.14.9, ONLYOFFICE Desktop Editors, Python 3.9 (chp-site, stdlib only), bash, pytest.

**Spec:** `docs/superpowers/specs/2026-11-12-iso-0.7.0-design.md`

## Global Constraints

- chp-site stays stdlib-only and Python 3.9-compatible.
- No new listener or port on any existing host in Track B. Track A's spike may open HTTPS on the spike server only.
- Spike hosts are lab VMs named `iso5-*` only; the existing lab (iso5-srv, iso5-cli1, iso5-cli2) may be reset
  (owner: lab reset is part of 0.7.0). Any qcow2 image over 120 GB virtual uses the 50 GB size guard.
- NextCloud must not reach the internet (owner anti-goal). The spike proves it; no "temporarily allow" for app
  downloads: apps come from an offline bundle.
- No secrets, passphrases, tokens or escrow contents in committed files (public repo).
- Owner decisions to honour verbatim: sign-in through Kanidm with one more authenticator enrolment in Kanidm
  (host sign-in unchanged); browser editors off; CUI/FCI/Archive team folders with sharing off; reviewers see CUI
  only if also `cui-users`; approvers ISSO + delegates, never the author; ONLYOFFICE-on-FIPS fallback decided by the
  owner after the spike.

## Review Focus

- Check 76 with a stale NFS-like mount making `df` exit 1 while other output is valid → the valid mounts are still
  checked, one ALERT for the unreadable state (`test_76_partial_df_output_still_checks_other_mounts`, Task 4).
- Two nightly review builds started at once (timer + manual) → exactly one writes; the other exits cleanly
  (`test_concurrent_builds_one_writes`, Task 5).
- A multi-day sign that stops on day N because a concurrent signer took it → the message names the days already
  signed (`test_partial_multi_day_sign_names_signed_days`, Task 6).
- The spike's outbound block: NextCloud's PHP process attempting any non-local connection → refused and logged
  (Task 1 proof, `SPIKE-NEXTCLOUD.md` §Outbound).
- ONLYOFFICE Desktop under FIPS: opening, saving and exporting PDF of a marked docx without crypto errors (Task 3
  proof; the result feeds the owner's TBD decision).
