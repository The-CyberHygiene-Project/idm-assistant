# ISO 0.7.0 Plan 3: the controlled-document workflow

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an author on a CHP workstation checks a controlled document out of NextCloud, edits it in ONLYOFFICE
Desktop on the encrypted disk, gets a delegate's approval, and publishes it server-side: marked, tagged, versioned,
hash-chained in the approval ledger, alerted and backed up. Plan 2's carried defects and review gaps are closed first.

**Architecture:** product versions of the spike's L1 route and transport (`lab/docs-spike/proto/`):
- A second NextCloud app, `chp_ledger`, in `nextcloud-chp`. It takes requests over NextCloud's HTTPS on 8443,
  stamps them with the authenticated user and the Kanidm session, and spools them. It never writes the ledger or
  the Compliance areas itself.
- A root appender, `chp_site/doc_ledger.py`, started by `chp-docs-ledger.path` (units in `chp-documents`).
  - It re-checks every Bearer at Kanidm and applies the rules.
  - It writes the hash-chained ledger.
  - It does the server-side publish (compare-and-write under a lock) into Compliance areas that are read-only to
    every user.
- The workstation commands `chp-site doc …` (`chp_site/doc.py`) sign in through a Kanidm public client `chp-doc`
  (PKCE, loopback redirect, tokens in tmpfs).
- A stdlib marking checker (`chp_site/marking.py`) is used on both ends.
- Marked templates and SSP narratives go in chp-templates 1.4.0.
- ONLYOFFICE Desktop is re-signed into our repo, with a `chp-onlyoffice` RPM carrying gates G2-G4 for the
  workstation.

Plan 4 builds the ISO and runs the full gates.

**Tech Stack:** Rocky 9.8 (FIPS, SELinux, fapolicyd, CUI profile); NextCloud 35.0.3 (PHP 8.3, PostgreSQL 16);
Kanidm 1.11 OIDC; Wazuh 4.14; ONLYOFFICE Desktop Editors 10.0.0; poppler-utils (`pdftotext`); Python 3.9 stdlib
(chp-site; docx/xlsx read with `zipfile` + `xml.etree`); bash; pytest.

## Global Constraints

- **Controlled documents only** go through checkout/approve/publish:
  - SSP, POA&M, policies, procedures, runbooks, change records, evidence.
  - They live in `CUI/Compliance` (CUI) and `Internal/Compliance` (non-CUI). The second location is my call;
    the spec says only "a non-CUI Compliance area".
  - Both areas are **read-only to every user by ACL**; only the root appender writes them.
  - Ordinary CUI files are uploaded through the browser without approval (unchanged from Plan 2).
- **Names:** `CUI_` or `FCI_` prefix in the CUI area, none in the non-CUI area; `_vX.Y` version; `-DRAFT` while in
  progress. Supersede, never delete: the replaced version moves to `Archive/Superseded` (CUI) or
  `Internal/Compliance/Superseded` (non-CUI).
- **Freshness** = the sha256 of the canonical bytes + the NextCloud file id, recorded **by the server** at checkout.
  The client's value is never trusted. ETag is a pre-check and `If-Match` only.
- **Author per cycle:** a cycle runs from the last publish (or creation) to now. Authors = the creator + everyone
  who checked the document out in the cycle + the publisher.
  - The approver must be outside Authors, must approve after the cycle's last checkout, and must approve that
    exact sha256.
  - The publisher must be in Authors.
- **Approvers:** the Kanidm accounts in new site keys `DOC_ISSO_ACCOUNT` and `DOC_APPROVER_ACCOUNTS` (comma list).
  `ISSO_NAME`, `REVIEW_DELEGATES` and the review sign-off stay unchanged.
- **ISSO override:** only when no approver account other than the author exists. A reason is required. It is
  ledgered, flagged in the next daily review, and alerted at once.
- **Every approval and every override alerts at once** through `ALERT_HOOK` (Wazuh level 12, owner decision 9).
  Publications are level 7.
- **Ledger:** `/var/lib/chp-docs/ledger/ledger.jsonl`, root 0600 in a 0700 directory.
  - One JSON line per entry, each carrying the sha256 of the line before; written under `flock`; a `ledger.head`
    witness.
  - The head is exported to the site stick with the existing export. `verify` exit codes are the same as
    `review_ledger`'s.
  - SHA-256 everywhere; FIPS refuses MD5.
- **Identity** comes only from what Kanidm's `chp-doc` userinfo returns for the Bearer, checked by the appender.
  - Approve and override need a verified Bearer. App passwords and Login Flow v2 are refused.
  - On a Kanidm outage the request is retried, not quarantined.
- **No new network port:** NextCloud's 8443 only. Tokens go in `$XDG_RUNTIME_DIR` (tmpfs). No long-lived secret
  is stored in plain text.
- **Marking:** the approved hash covers the finished, marked file. Marks are inserted only into `-DRAFT` files,
  before approval, with a dry run. Reader PDFs are derived last from the approved file. The checker runs on the
  workstation **and again on the server** at publish.
- **Marking values** come from new site keys: `CUI_CONTROLLED_BY`, `CUI_CATEGORY`, `CUI_POC`. They are never typed
  per file.
- **ONLYOFFICE:**
  - It ships as the re-signed vendor RPM (sha256 pinned) plus `chp-onlyoffice`.
  - AI Tools are removed, and its start-page vendor calls are blocked.
  - Per-application egress on the workstation (G3) and the autosave sweep (G2) are in force.
  - Its non-validated bundled crypto is a POA&M item.
- **Kept from Plan 2:** chp-site is stdlib-only on Python 3.9; site keys are optional and additive; no secrets in
  the public repo; the build VM is used for PHP content; aero's fapolicyd is not changed; nothing is signed except
  by the owner's YubiKey.

## Review Focus

- **The canonical copy changes between the publish check and the write** (a second publish, or an admin edit).
  The compare-and-write under the lock refuses, with nothing written and nothing ledgered as published.
  Pinned by `test_publish_race_refused` (Task 4).
- **An approver checks the document out to read it, then approves.** They become an author in this cycle and are
  refused, with a plain message saying why. Pinned by `test_reader_checkout_makes_author` (Task 4).
- **Kanidm unreachable, or the 15-minute token expiring between `approve` and the appender's userinfo call.**
  The request is retried or the user is told "pending, run again". It is never quarantined, and never refused
  after a successful append. Pinned by `test_kanidm_outage_retries` and `test_expired_token_mid_request` (Task 4)
  and `test_refresh_before_send` (Task 6).
- **A marked docx with the banner in a text box or shape instead of the header/footer part, and an xlsx with the
  banner only on the first sheet.** Reported as missing marks (it does not mark every page), never passed.
  Pinned by `test_banner_in_textbox_is_missing` and `test_xlsx_every_sheet` (Task 5).
- **A document name with spaces, non-ASCII (NFD vs NFC) or a second `_v` in the title.** Parsed the same on both
  ends; refused with the name rule's message, never a stack trace. Pinned by `test_name_rule_edge_cases` (Task 5).
