# ISO 0.6.0 Implementation Plan (disk layout by disk size, check 76, sign-off fixes)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a new install sizes its volumes by disk and role (2 TB server: `/var` 100, `/var/log` 50, audit 30, ~340 GiB
unallocated; workstations their own layout), every host alerts before a volume fills, and four sign-off weaknesses
are closed; released as repo 0.11.0 and ISO 0.6.0.

**Architecture:** a new pure module `chp_site/layout.py` computes the volumes from (role, disk bytes); `render.disk_ks`
turns them into kickstart lines; `pre.py` passes the chosen disk's size and role and writes a disk note the kickstart
appends to the escrow file. Check 76 is a chp-base monitor script. The review fixes are local edits to
`review_ledger.py` and `cli.py`. Lab: a size guard on aero stops any VM whose sparse disk image grows past 50 GB.

**Tech Stack:** Python 3.9 (chp-site, stdlib only), bash monitor checks, pytest, Anaconda kickstart, libvirt/qcow2
on aero, RPM + the existing signing/release scripts.

**Spec:** `docs/superpowers/specs/2026-11-09-iso-0.6.0-design.md`

## Global Constraints

- Sizes are GiB in the spec, MiB in kickstart (`logvol --size`). No `--grow` in a sized layout.
- `/boot/efi` 1024 MiB and `/boot` 2048 MiB stay as today; the LUKS2 PV, `volgroup chp`, TPM binding unchanged.
- No console prompts in the installer; the 100 GB minimum (`choose_disk`) stays.
- Server system volumes fixed: `/` 90, `/var` 100, `/var/log` 50, `/var/log/audit` 30, `/var/tmp` 15, `/tmp` 15,
  swap 29 (329 GiB). Rest split: `/home` 15.6 %, `/data` 22.9 %, `/backup` 39.2 %, unallocated = remainder.
- Workstation fixed: `/` 40, `/var` 20, `/var/log` 20, `/var/log/audit` 8, `/var/tmp` 4, `/tmp` 4, swap 8 (104 GiB);
  `/home` 25 % of the rest (at least 10); no `/data`, no `/backup`.
- Small disks keep **today's layout byte-for-byte**: server below 900 GB (so 960 GB enterprise SSDs get the sized
  layout), workstation below 240 GB. Below 1.9 TB a server gets the disk note.
- `/data`, `/backup`: `nodev,nosuid`; `/backup` also `noexec`.
- Check 76 threshold 85 %; it never alerts on the file system check 72 watches.
- No new listener, port or package. Existing installs are not repartitioned.
- Lab: no qcow2 image may exceed **50 GB actual** (owner, 2026-11-09).

## Review Focus

- Two disks present (backup drive already in the bay) and the hosts table names one: the other disk is never
  touched → `test_second_disk_is_never_in_the_kickstart` (Task 2).
- A disk just above or below a threshold (899/900 GB server, 239/240 GB workstation, 1.9 TB note) → boundary
  tests (Task 1).
- Volume sizes plus overhead must never exceed the volume group, or Anaconda stops mid-install with a
  console error → `test_volumes_always_fit` over a range of sizes (Task 1).
- Check 76 on a host where `df` fails or lists a read-only/ISO mount → no crash, no false alarm
  (`test_76_df_failure_alerts_once_and_ignores_non_xfs`, Task 3).
- A signer who pipes `yes` from a script or runs over `ssh -n` → refused with a plain message
  (`test_sign_refuses_without_a_terminal`, Task 4).
