What the dc2 installer (custom Rocky ISO + signed RPM repo + kickstart) should set **by default**, each with the lab evidence behind it. Status: **R** = requirement (evidence in hand), **D** = needs an ISSO decision, **O** = open.

| 34 | SSH CA | the SSH CA records every certificate it issues (public) and registers each user's public key; re-issue signs only the registered key, short validity (+1h in the lab), and users need a self-service renewal path | Plan 7 C3 (3/3) | R |
| 35 | sshd | TrustedUserCAKeys lives in a drop-in the ISO owns, the key file pinned by fingerprint; drift check with `sshd -T`; any change validated with `sshd -t` before reload | Plan 7 C4 (3/3) | R |
| 36 | GDM | GUI on both roles: `pam_kanidm` + GA on `gdm-password`, tokens host-local (row 11); a scripted PAM test of the `gdm-password` stack (and the token label afterwards) joins the regression | dc1 gdm/`xdm_t` lockout; design 2026-09-29 | R |
| 37 | Packages | verify the install repo **before** installing: Anaconda installs with `gpgcheck=0` and `repo_gpgcheck=0`, so the kickstart `%pre` must check the ISO repo's `repomd.xml.asc` against the pinned project key (this covers every package through the metadata checksums) and stop on failure. It must verify whatever repo is actually used, including a `chp.repo=` kernel-argument override (a lab hook), or the release kickstart drops that override | ISO Plan 2 proof (`lab/iso2/PROOF-RECORD.md`, finding 7); ISO Plan 5a: `chp-site verify-repo` in `%pre`: a tampered repo is refused and an unreadable one fails closed, both before any disk is touched (`lab/iso5/PROOF-RECORD.md`) | R |
| 38 | Removable media | USBGuard (CUI) blocks USB storage on installed hosts. The **site stick** is pinned (USB identity recorded at install in `/etc/chp/site-stick.id`; the USBGuard device hash is pinned on first use), and `chp-site` allows **only that stick, temporarily** (`usbguard allow-device`, no policy change), blocking it again afterwards. Any other stick is refused. **Limits:** the pin guards against *mistakes* (the wrong stick), not a determined attacker with physical access (USB identity, serial and descriptors can be spoofed, and the hash pin is trust-on-first-use); a pinned device must be storage-only (a composite device, e.g. with a keyboard interface, is refused) | ISO Plan 3a proof (`lab/iso3/PROOF-RECORD.md`; ISSO + user decisions 2026-09-30) | R |
| 39 | Identity ops | `chp-site revoke` clears the kanidm-unixd cache on **every client** (ISSO #28): the server's **cache key** (ECDSA P-384, made at first boot, `/var/lib/chp/cache-key/`, public half in `client.conf` `CACHE_PUBKEY`) is accepted on each client by a locked `chpcache` account **only** `from="<server IP>"` and **only** for `command="sudo -n /usr/bin/kanidm-unix cache-invalidate"` (`no-pty,no-port-forwarding,no-agent-forwarding,no-X11-forwarding`; sudoers: exactly that command). Client host keys are trust-on-first-use in a dedicated `known_hosts`; an unreachable or re-keyed client is named, and the Kanidm change stands | ISO Plan 3b (user/ISSO decision 2026-09-30); server half proven on a fresh install from repo 0.3.3 (`lab/iso3/PROOF-RECORD.md`: key made at first boot, pinned in `client.conf`, an unreachable client named while the change stands); client half + fan-out proven on 2 clients in ISO Plan 4a (`lab/iso4/PROOF-RECORD.md`: revoke cut access in 1-3 s) | R |
| 40 | Identity ops | `chp-site unexpire` re-enables an expired account **only** with an approver who is `ISSO_NAME` or in `UNEXPIRE_DELEGATES` and a one-line reason (10-300 chars); both are written to the Linux audit log (`auditctl -m`, type USER) and authpriv **before** the change (no record, no change) and after it (ISSO #32). `onboard` never re-enables an expired account; `revoke`/`unexpire` refuse the built-in admins and `revoke` refuses the operator's own session account. Kanidm commands run under the operator's own session; `chp-site` never handles a password; reset tokens go to `/root/chp-onboard/` (0700/0600), never the screen | ISO Plan 3b, proven on a fresh install from repo 0.3.3 (`lab/iso3/PROOF-RECORD.md`: 23/23; `auditctl -m` records under the CUI profile) | R |
| 41 | Identity ops | each client's kanidm-unixd uses its **own read-only token** (service account `unixd-<host>` in `idm_unix_authentication_read`, token minted at server first boot or by `chp-site client-token HOST`, carried on the site stick as `tokens/<host>.token`, installed 0600 `/etc/kanidm/token`). A lost client is cut off with `kanidm service-account delete unixd-<host>` without touching the others. Open: old tokens are not revoked when a new one is minted (deferred, Plan 4a review) | ISO Plan 4a (user decision 2026-09-30; `lab/iso4/PROOF-RECORD.md`) | R |
| 42 | Second factor | GA enrolment is admin-assisted at the host (`sudo chp-site ga-enrol USER`, QR + 5 scratch codes to that terminal only, audited; root enrols a host's first admin); **POA&M:** move to a one-time, short-lived enrolment link by mail once the server sends mail (never the QR image itself) | ISO Plan 4b (ISSO decision 2026-10-01 #1; `lab/iso4/PROOF-RECORD.md`) | R |
| 43 | Second factor | GA applies to Kanidm users only; local accounts (root console, chpadmin, diag, chpcache) are exempt via `pam_localuser` (break-glass, as on dc1) — **SSP deviation**; proven with the directory down; lost phone = 5 one-time scratch codes, admin `ga-enrol --reset` as backup; faillock counts GA failures | ISO Plan 4b (ISSO decisions 2026-10-01 #2/#3; `lab/iso4/PROOF-RECORD.md` run 2: 59/59) | R |
| 44 | Lockouts | the engine may clear a workstation lockout (`faillock-reset`) only with a person's approval on the decision form, and never while TOTP_TIME_SKEW, TIME_UNVERIFIED or SELINUX_LABEL_WRONG is found (the cause is fixed first; the model is not offered the reset); the form shows the failures' times and sources | lockout scenarios F1, F2 (3/3 each) | R (decided 2026-10-03, ISSO) |
| 45 | DNS faults | name-resolution faults are diagnosed only: no repair is offered or run for DNS_LOOKUP_FAILED or DNS_WRONG_ADDRESS; a name resolving to an address the identity server does not have is a possible security incident (the ISSO is told and the record is examined before anyone changes it) | DNS scenarios D1, D2 (3/3 each) | R (decided 2026-10-03, ISSO) |
| 46 | fapolicyd | with a person's approval the engine may refresh fapolicyd's trust from the package database (`fapolicyd-trust-refresh`) when a denied program belongs to an installed package signed by a pinned key (Rocky 9, EPEL 9, the project); it never trusts an unpackaged, unsigned or unknown-key program, and fapolicyd permissive/off is diagnose only (both enforced in the allow-list). Injection ship test on the real path 5/5; with the gate bypassed the model followed a plausible planted instruction 3/5 (recorded, not a gate: the code is the gate). The refresh reloads the whole package database, so it refuses unless every never-loaded package carries a pinned key and no trust-file entry waits. Limit: the signer is the key ID the package header claims, not re-verified (hosts import only the project key); backlog: import the Rocky and EPEL keys so the collector can verify | fapolicyd scenarios P1, P2, P3 (3/3 each) | R (decided 2026-10-03, ISSO) |

Decisions for the former D rows were settled one at a time on 2026-09-29; the full wording is in `docs/superpowers/specs/2026-09-29-chp-appliance-iso-design.md` §2.

ISO Plan 3a (2026-09-30) proved rows 15, 16, 17, 23, 24, 26 and 31 on an **installed appliance server** (fresh install from signed repo 0.3.1): TPM binding and unattended unlock, kickstart copies shredded, read-only collector token, certificate monitors, ACME re-issue of an expired certificate, and the pinned site root. See `lab/iso3/PROOF-RECORD.md`.

Shredding (`chp-site` escrow move, `firstboot-common`) is **best effort**: overwrite + fsync + unlink. XFS reflink and SSD wear levelling can keep old blocks; LUKS protects what remains (final review of ISO Plan 3a).
