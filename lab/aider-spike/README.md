# aider spike (2026-10-01 to 10-03): a write-capable coding agent in the repair path

**Throwaway experiment, kept as evidence.** The question: can a local language model, driven by the `aider` coding
agent, diagnose and repair identity faults on the lab hosts if every change goes through a human approval gate? The
answer shaped the project's design: **code diagnoses and repairs known faults; the model only explains; the agent stays
off the repair path.**

## Setup

- `aider` 0.86.2 with local models served by LM Studio on the Mac (Devstral Small 2 2512, gpt-oss-20b; Gemma was
  tried and timed out). Run only through `run-aider.sh`, inside a macOS sandbox (`sandbox.sb`) that blocks all network
  access except the local model server.
- **Bench** (`bench.py`, `nobook.py`, `withrefs.py`, scored by `score.py` / `score2.py` with `safety.py`): real
  appliance config files broken like the lab's fault scenarios, many trials per case and model. "Runbook" cases tell
  the model the fault; "no-runbook" cases give only the symptom. `results/` holds the raw trials (JSON lines).
- **Live gate** (`live.py`, `gate.py`, `test_gate.py`, `dryform.py`, `diag.py`): the agent proposes edits to copies
  of client2's config in the sandbox; a person approves each change at a gate; the gate backs up, applies, can revert,
  and keeps a hash-chained log.

## What it found

- **With the fault named (runbook cases), the models fixed most of them** (8 of 9 cases with reference passages); with
  only the symptom they did poorly, and some edits **weakened security** (for example removing a sign-in step or
  shutting out the emergency account). The safety checker in `safety.py` was written to catch those.
- **gpt-oss-20b's edits were silently dropped** in 40 of 130 trials: aider switches to four-backtick fences when any
  file in the chat contains three backticks, and that model kept writing three. Converting ``` to ~~~ in reference
  files fixed it.
- **Live, six runs, no fault was fixed.** Without a diagnosis the model weakened a security control 3 times out of 3
  (opening logins to every account, passwordless root); given the engine's finding it aimed at the right cause every
  time but missed host-specific details (a required `--force`, a certificate path, the certificate itself).
- **The gate itself had real bugs that only the real host exposed**, e.g. a revert that emptied a file because the
  host's login banner got into the backup, and a copy into a directory treated as a clean backup. All were fixed with
  tests (`test_gate.py`).
- **The operator could not judge raw diffs.** That led to the plain-language decision form (problem, cause, action,
  downside, choice), typed whole-word answers with Enter, and a result screen — now part of the engine
  (`engine/form.py`).

## Not included

aider's own Python environment (about 740 MB), logs, the reference passages (third-party manual pages, regenerated by the
scripts), and the per-run copies of lab host configuration and gate logs.
